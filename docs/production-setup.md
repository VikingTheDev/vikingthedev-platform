# Production setup: Coolify and GitHub

The maintainer's console work for M1b phase 2 (M1b gate). Cloudflare is in [`edge-config.md`](edge-config.md). Claude never sees the values marked **secret**: type them into the console yourself, and never paste them into a session.

Image names are a default from M1b phase 1: `ghcr.io/vikingthedev/vikingthedev-platform/<target>`, where `<target>` is `api`, `homepage` or `canary`. CI's `publish` job pushes `:<sha>` and `:prod` there on every push to `main` (M1b phase 3a).

**Order:** PostgreSQL, Valkey and Cloudflare need no images, so they come first. The app resources wait until `publish` has run once. Then, under each package's *Package settings*, set the visibility to **Public** (M1b gate), so Coolify pulls without a registry credential. GHCR creates packages as private.

## Coolify

Create everything in one project (`vikingthedev`), environment `production`, on the existing server.

### Rules for every resource

- **Memory:** set both *Maximum Memory Limit* and *Memory Swap Limit* to the limit from [`capacity.md`](capacity.md), so a container never swaps past it.
- **Ports:** never fill in *Ports Mappings* or make a database *publicly available*. A published port bypasses `ufw` (D20). Traefik reaches the apps through *Ports Exposes* alone.
- **Proxy:** in the server's *Proxy → Configuration*, remove the `8080:8080` port mapping. Traefik's `:8080` entrypoint isn't used (D20).
- **Environment variables:** runtime only. Leave *Build Variable* unticked. Lock the **secret** ones so the UI hides them.
- **Deploys:** *Auto Deploy* off. Only the Deploy Webhook, called from Actions, deploys.
- **Health check:** leave Coolify's health check off. The distroless images have no `curl` or shell for it, and CI's health wait replaces it.
- **Hardening, app resources only** (API, homepage, canary): in *Custom Docker Options*, add `--cap-drop=ALL`. Coolify 4.4.6 silently drops `--read-only`, so the apps run with a writable root filesystem (accepted, M1b phase 2). Coolify 4.4.6 rejects `--security-opt=no-new-privileges` here (`invalid security-opt: "\"no"`), so it's left out; ADR 0009 defers Docker's daemon-wide setting as voluntary hardening. The database images start as root and drop privileges themselves, so they get no custom options.

### API

| Setting | Value |
|---|---|
| Type | Docker Image: `ghcr.io/vikingthedev/vikingthedev-platform/api`, tag `prod` |
| Ports Exposes | `8080` (`:8081` stays internal: no domain, ever) |
| Domains | `<scheme>://vikingthe.dev/api,<scheme>://canary.vikingthe.dev/api` |

`<scheme>` is `http`: the apps tunnel (`cloudflared@apps`) sends every host to `http://localhost:80`, Traefik's `http` entrypoint (step 14, 2026-10-23). Step 14 still confirms there's no redirect loop once the apps are deployed (ADR 0003).

### Deploy token and webhooks

1. *Settings → API*: enable the API.
2. *Keys & Tokens → API tokens*: create `github-actions-deploy` with the **deploy** permission only. Copy it straight into GitHub's `COOLIFY_TOKEN` (below).
3. Copy each app resource's *Deploy Webhook* URL into GitHub (below).
4. Cloudflare Access: confirm the Bypass rule on `coolify.vikingthe.dev/api/v1/deploy` exists (ADR 0003 point 4). The deploy-only token still guards that path.

## GitHub

### `production` environment

*Settings → Environments → New environment*: `production`.

- **Deployment branches:** *Selected branches*, `main` only.
- **Environment secrets** (all **secret**):

  | Name | Value |
  |---|---|
  | `COOLIFY_TOKEN` | the deploy-only token |
  | `COOLIFY_WEBHOOK_API` | the API's Deploy Webhook URL |
  | `COOLIFY_WEBHOOK_HOMEPAGE` | the homepage's Deploy Webhook URL |
  | `COOLIFY_WEBHOOK_CANARY` | canary's Deploy Webhook URL |
  | `CLOUDFLARE_API_TOKEN` | the cache-purge token from `edge-config.md` |

- **Environment variable** (not secret): `CLOUDFLARE_ZONE_ID`, from the zone's *Overview* page.

Nothing goes into repository-level secrets, so pull request jobs never see these (CLAUDE.md).

### Actions settings

*Settings → Actions → General*:

- **Actions permissions:** *Allow select actions*: GitHub-authored actions, plus the approved list in `.claude/rules/ci-deploy.md`. Tick *Require actions to be pinned to a full-length commit SHA*.
- **Fork pull request workflows:** require approval for all external contributors.
- **Workflow permissions:** *Read repository contents*. *Allow GitHub Actions to create and approve pull requests* off.

### `main` ruleset

Edit the existing ruleset from M0 (it already blocks deletion and force-pushes):

- **Require a pull request before merging:** 0 approvals.
- **Require status checks to pass:** `checks-passed`, source *GitHub Actions*. It's the only required check: it always runs, so a docs-only PR can merge (ci-deploy.md).
- **Bypass list:** empty.

Add the status check after the `m1b` PR's first CI run, since GitHub offers only check names it has seen.
